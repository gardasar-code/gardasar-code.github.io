# CONNECTION — как Di2 Field подключается к переключателю

> Описание процесса связи по BLE: **что** происходит, **где** в коде и **как** этим
> управляет пользователь. Технические детали протокола — в `NOTES.md`.

---

## TL;DR для пользователя

1. Добавь поле Di2 на страницу данных тренировки на Edge.
2. **Разбуди Di2** — щёлкни любым переключателем (в покое он спит и не виден в эфире).
3. Поле само находит ближайший Di2 и подключается — точка станет зелёной, появятся цифры.
4. Поле «прилипает» к этому Di2 (sticky-lock) и при следующих заездах цепляется именно к нему.
5. Сменить байк/переключатель: настройки поля → **Forget paired Di2** → включить и сохранить.

Кнопки «подключиться» нет и быть не может: это data field, он не принимает нажатий.
Связь поднимается автоматически, как только поле на экране и Di2 проснулся.

---

## ЧТО происходит (этапы связи)

| Фаза (`Di2State.phase`) | Что делает поле | Что видит пользователь |
|---|---|---|
| `CONN_SCANNING` | сканирует эфир, фильтрует устройства по advertised-UUID Shimano | синяя пульсирующая точка, текст **Searching…** + подсказка **Wake the Di2** |
| `CONN_CONNECTING` | нашёл цель, поднимает соединение и подписку на notify | жёлтая точка, текст **Connecting…** |
| `CONN_LIVE` | подписан на передачи, читает батарею | зелёная точка (тёмно-синяя, если привязаны), крупные цифры передачи |
| `CONN_RETRY` | связь потеряна, ждёт следующей попытки скана | оранжевая точка, снова **Searching…** |

Реконнект **бесконечный** с нарастающим интервалом (3→30 с): поле никогда не «сдаётся»,
связь восстановится сама, как только Di2 снова проснётся.

**Тёмно-синяя точка** (вместо зелёной) при `CONN_LIVE` = sticky-lock активен: связь есть
и это привязанный Di2. Зелёная live-точка — подключены, но привязки нет (первый запуск
или после Forget — взяли ближайший проснувшийся). Флаг `Di2State.locked`, цвет выбирает
`Di2FieldView.phaseColor()`. (Прежний индикатор — чёрное кольцо вокруг точки — убран:
налезал на текст «Di2» и сливался с тёмной темой.)

## ГДЕ это в коде

| Шаг | Файл / метод |
|---|---|
| Старт BLE при запуске поля | `Di2FieldApp.onStart` → `Di2BleDelegate.start()` |
| Регистрация профилей (батарея + notify) | `Di2BleDelegate.registerProfiles()` |
| Скан эфира | `Di2BleDelegate.startScan()` / `onScanResults()` |
| Выбор устройства (RSSI / sticky-lock) | `Di2BleDelegate.onScanResults()` |
| Подключение | `Di2BleDelegate.connectTo()` → `onConnected()` |
| Подписка на передачи (CCCD) | `Di2BleDelegate.enableNotifications()` |
| Парсинг передач | `Di2BleDelegate.onCharacteristicChanged()` → `parseGearPacket()` |
| Чтение батареи | `Di2BleDelegate.readBattery()` → `onCharacteristicRead()` |
| Heartbeat (реконнект, опрос батареи, анимация) | `Di2FieldView.compute()` → `Di2BleDelegate.onTick()` |
| Реконнект с backoff | `Di2BleDelegate.scheduleReconnect()` |
| Отрисовка статуса/индикатора | `Di2FieldView.drawStatus()` / `phaseColor()` / `dotRadius()` |

Поток данных: `Di2BleDelegate` (писатель, async BLE-колбэки) → `Di2State` →
`Di2FieldView` (читатель, `onUpdate`).

### Ключевые UUID (подтверждены, см. `NOTES.md`)

- Advertised-маркер Shimano (фильтр скана): `000018ff-…`
- Notify передач (CCCD-подписка): сервис `000018ef-…`, характеристика `00002ac1-…`
- Батарея D-Fly (Read): стандартные `0000180f` / `00002a19`, процент в байте[0]

## КАК выбирается переключатель (sticky-lock + Forget)

### Проблема

«Сильнейший по RSSI» хватает ближайший Di2. Если рядом два байка — поле прицепится
к более громкому, а не к нужному.

### Решение: привязка по имени устройства

- При первом подключении поле запоминает **имя** устройства (`Device.getName()`) в
  `Application.Storage` (ключ `lockedDi2Name`). Имя — единственный дискриминатор,
  который BLE API даёт сохранить между сессиями (адрес устройства не персистится).
- На последующих сканах подключаемся **только** к устройству с этим именем
  (`onScanResults()` сравнивает `ScanResult.getDeviceName()` с сохранённым).
- Привязка переживает перезапуск поля и смену страниц.

**Запасной путь.** Если эфирное имя в скане недоступно (не пришло в рекламе), но
вокруг ровно **один** Shimano-кандидат — подключаемся к нему (одиночный Di2 почти
наверняка «свой»). Если кандидатов несколько и совпадения по имени нет — поле ждёт,
не хватая чужой переключатель.

### Forget — сменить переключатель

Настройки поля в Garmin Connect Mobile → **Forget paired Di2**:

1. Включи тоггл и сохрани.
2. Поле снимает привязку (`applyForgetIfRequested()`), рвёт текущее соединение и
   сканирует заново (`onSettingsChanged()` в делегате).
3. Цепляется к ближайшему Di2 и «прилипает» уже к нему.
4. Тоггл **выключается сам** — он работает как одноразовая кнопка, а не режим.

Чтобы выбрать конкретный из двух: поднеси Edge к нужному байку (или держи второй Di2
спящим), затем нажми Forget и сохрани — поле захватит ближайший проснувшийся.

## Поведение в симуляторе

В `:debug`-сборке (F5 / симулятор) BLE **выключен** (`Di2FieldApp.bleEnabled()` → false):
эмулятор BLE симулятора крашится на macOS 26+. `Di2FieldView.applyDebugData()` форсит
`connected = true` и подставляет тестовые передачу/батарею из Storage, поэтому
статус-экран и анимация поиска в симуляторе не видны — их проверяют на устройстве
(release-сборка). Калибровка протокола передач — `DEBUG = true` в `Di2BleDelegate`.

## Короткое описание для стора / About (EN)

> **How it connects.** Add the Di2 field to a data screen, then wake your Di2 by
> tapping a shifter (it sleeps when idle). The field finds the nearest Di2 over
> Bluetooth and connects automatically — no button to press. It then sticks to that
> shifter on future rides. Riding a different bike? In the field settings turn on
> **Forget paired Di2** and save: it releases the current unit and locks onto the
> nearest one on the next scan.
