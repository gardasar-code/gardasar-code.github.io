# Логирование на устройстве (диагностика BLE)

Как снять отладочный лог Di2 Field с реального Edge. Нужно, например, чтобы
проверить, рекламируется ли Di2 после пробуждения без ручного паринга
(вопрос авто-реконнекта).

## Два канала диагностики

| Канал | Сборка | Кто может | Глубина |
|---|---|---|---|
| **On-screen overlay** (настройка `diagOverlay`) | любая store-сборка | любой пользователь (фото экрана) | агрегат скана + сырой notify-пакет |
| **Файловый лог** (`System.println` → `*.TXT`) | только sideload-diag (`build-diag.sh`) | энтузиаст с USB | полная хронология BLE-событий |

Файл-лог в release **не пишется** (ограничение CIQ — см. «Почему это не просто
включить»). Поэтому для массового онбординга неподдержанных устройств служит
on-screen overlay: он рисуется в `onUpdate` (это не `println`) и работает в
обычной store-сборке.

## On-screen overlay (массовый путь)

Пользователь включает в настройках Connect IQ тоггл **«Diagnostics overlay»**
(`diagOverlay`) → экран целиком отдаётся под диагностику → присылает ФОТО. Без USB,
без создания файлов, без sideload. Основной макет (крупные передачи/батарея) при этом
не рисуется — место занимает максимум технических данных.

Строки diag-экрана (`Di2FieldView.drawDiagScreen`):

| Строка | Значение |
|---|---|
| `● <Phase>` | СВЕТОВОЙ индикатор этапа: цветной кружок (фаза) + слово (Scanning/Connecting/Live/Retry) |
| `dev=N shi=M r=-XX` | устройств в эфире всего / с Shimano-маркером `000018ff` / лучший RSSI |
| `lk=0/1 bat=Y%` | sticky-lock и заряд D-Fly |
| `id=<имя>` | GATT-имя устройства (модель переключателя; в эфире скана недоступно) |
| `mdl=<профиль>` | распознанный профиль серии Di2 (или `?` для неизвестной модели) |
| `R=r/rt F=f/ft R.RR` | распарсенные задняя/передняя передачи + передаточное отношение |
| `len=K` | длина последнего notify-пакета |
| `<hex>` ×N | сырые байты последнего notify по 8 в строке (любой длины — для разбора серии) |

Триаж по `dev`/`shi`:
- `dev=0` — BLE-стек вообще ничего не видит (Bluetooth выкл / Di2 не вещает).
- `dev>0, shi=0` — в эфире есть BLE, но Di2 **не под нашим маркером** `000018ff`
  (другая серия Di2 → нужно расширять scan-фильтр).
- `shi≥1` — наш маркер виден; смотрим этап/`len`/hex/`id`/`mdl` для разбора коннекта и формата.

## Почему это не «просто включить» (файловый лог)

Connect IQ-приложение **не может создавать произвольные файлы** — единственный
файловый канал это `System.println`, и работает он только при двух условиях:

1. **Debug-сборка** (без флага `-r`). В release/store `System.println` в файл не
   пишется. Но в обычной debug-сборке BLE выключен (`bleEnabled()=false`,
   симулятор BLE нестабилен). Поэтому диагностику собираем спец-скриптом
   `build-diag.sh` — он форсирует BLE on в debug-копии исходников.
2. **Файл лога создан заранее, вручную.** Устройство пишет в
   `GARMIN/APPS/LOGS/<имя_prg>.TXT`, но сам файл не создаёт. Нет файла — вывод
   молча теряется (именно поэтому ранее лог «не появлялся»).

Дополнительно: имя `.txt` должно **точно** совпадать с именем `.prg`; лимит файла
~5 КБ, при заполнении старое уходит в `.BAK`.

## Пошагово

1. Собери диагностический билд:
   ```bash
   ./build-diag.sh        # -> bin/DI2DIAG.prg
   ```
2. **Удали с устройства бета/стор-версию Di2 Field** (иначе сайдлоад дата-филда
   может получить другое внутреннее имя, и матчинг `.txt` сломается).
3. Скопируй `bin/DI2DIAG.prg` в `GARMIN/APPS/` (OpenMTP на macOS).
4. Создай **пустой** файл `GARMIN/APPS/LOGS/DI2DIAG.TXT` (папку `LOGS` при
   необходимости создай сам).
5. Полностью закрой Garmin Express / синхронизацию, отмонтируй устройство.
6. Добавь поле на экран данных, **запиши активность**, прогони сценарий
   (например: подключился → дал Di2 уснуть → покрутил педали без паринга).
7. Подключи устройство, забери `DI2DIAG.TXT` (и `DI2DIAG.BAK`, если есть).

## Формат строк

Каждая строка: `<seq:4> <t_ms> | <сообщение>` (`Di2Log.line`).
`t_ms` — `System.getTimer()`, монотонные миллисекунды от старта (для интервалов).

Ключевые события (источник — `Di2BleDelegate`, флаг `DEBUG`):

| Сообщение | Значение |
|---|---|
| `scan: shimano=N best=… rssi=… lock=…` | результат скана: видим ли Di2 в эфире |
| `pairDevice name=… rssi=…` | попытка поднять соединение |
| `connected` | подписка на notify установлена |
| `notify char=… bytes=[…]` | сырой пакет передач (калибровка) |
| `disconnected` | разрыв связи |
| `reconnect scheduled in N ticks` | запланирован повторный скан |

## Диагностика авто-реконнекта

Смотри строки `scan:` после того, как Di2 «уснул»:

- `shimano≥1` **без** ручного паринга → устройство само рекламируется, проблема
  в нашей логике подключения (чиним кодом).
- `shimano=0` до ручного паринга → D-Fly в спячке не вещает connectable-рекламу;
  ручной паринг неизбежен (ограничение прошивки Di2).

## Перед публикацией в Store

`DEBUG` в `Di2BleDelegate.mc` вернуть в `false` (release-логи не нужны, экономия
кода/ресурсов). Диагностический билд (`build-diag.sh`) и `DI2DIAG.*` в стор не
идут — это только сайдлоад.
